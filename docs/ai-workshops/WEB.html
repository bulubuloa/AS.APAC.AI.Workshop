Learning outcomes and tool choice

Participants will run an existing suite, inspect a trace, write an assertion around a dealer workflow, and review AI-generated code. Playwright is the web choice for browser support, locator auto-waiting, isolated browser contexts and an integrated HTML report, trace, screenshot and video workflow. The choice is supported by this working project; this POC does not prove it wins every benchmark against Selenium or Cypress.

Playwright controls the browser. Assertions decide whether behavior is correct. Codex or Claude Code can help inspect code and generate tests, but the reviewer must check the business rule and evidence. Official Playwright guide and Trace Viewer documentation.

Prepare and run the example

Install the Node version supported by the project and Git. Clone the repository, use the committed lockfile, and obtain approved UAT credentials. Review README.md and the environment template for the exact variable names. Store credentials in a local ignored .env file; do not paste them into prompts or commit authentication state.

git clone https://github.com/bulubuloa/AS.APAC.AI.Workshop.git
cd AS.APAC.AI.Workshop/roadside-web
npm ci
npx playwright install chromium
npx playwright test --list
npx playwright test
npx playwright show-report

Run only against the approved environment. Before running creation scenarios, confirm a dedicated account and unique test-data prefix. Review playwright.config.ts to identify base URL, projects and evidence retention. Never publish raw traces until checked for tokens, credentials and customer data.

Hands-on exercise: dealer detail

Start with an existing dealer test and reuse its authentication setup. Identify the actual link and popup behavior in the application. Assert a known test dealer value rather than merely asserting that the page opened. The following pattern is illustrative; use actual accessible labels and fixture values from the project.

const popupPromise = page.waitForEvent('popup');
await page.getByRole('link', { name: dealerName, exact: true }).click();
const detail = await popupPromise;
await expect(detail.getByText(dealerName, { exact: true })).toBeVisible();

Suggested AI prompt: “Read the current authentication setup and dealer tests. Add one test for the approved fixture dealer. Reuse existing helpers, use stable locators, assert the displayed business value, and keep secrets out of code. Explain any assumption and show the test result.”

Review checklist: the locator identifies the intended element; the expected value comes from a fixture or independently checked source; the test fails when the value is wrong; cleanup is safe; screenshots and traces explain the failure. A green test with no meaningful assertion proves little.

Pipeline plan and lab completion

Proposed pipeline: install locked dependencies and browser to preflight account/fixtures to run the required pack to enforce expected test count and reject failures/skips to publish sanitized HTML/JUnit and retained failure evidence. The local POC gate rejects empty or incomplete runs; cloud CI has not been deployed. Mutation tests should avoid automatic retries that can create duplicate records. Official CI guidance.

A participant finishes the lab when the selected test passes, a deliberate incorrect expected value produces an understandable failure, and the reviewed report can be opened. Submit the test diff and sanitized report, with the tested environment and suite scope recorded.
